# 江南 3D 资产工厂 v1

本文件把当前“程序化庭院 demo”升级为可扩张的历史写实武侠 3D 资产生产体系。目标不是一次生成一个好看的古风模型，而是持续生产**可复用、可组合、可验证、可进入游戏引擎**的资产。

## 1. 总原则

1. **历史与构造先于装饰**：建筑必须看起来能够承重、排水、维修和真实使用。
2. **模块先于整栋建筑**：门、窗、柱、梁、屋面、栏杆、石基优先做参数化母体。
3. **天气影响材质**：江南的雨、雾、潮气必须改变木、瓦、石、土的粗糙度与色值，而不是只加一层雾。
4. **克制武侠而非仙侠**：不依赖发光符文、巨大能量、漂浮建筑和高饱和特效。
5. **AI 生成资产必须经过 QA**：单张概念图或单次生成不等于生产资产。

## 2. 资产等级

### Hero
关键近景资产与地标。允许人工精修，优先质量，不追求全自动。

### Production
绝大多数模块化建筑、家具和环境道具。必须可批量复用和变体生成。

### Filler
小型杂物、散布物、落叶、碎石、贴花、远景填充。强调数量、随机性和低成本。

## 3. 首批 MVP

权威清单见 `asset_db/assets.json`。第一批 20 个 P0 资产覆盖：

- 石基、石阶、柱梁、墙、门、窗、屋顶；
- 石板路与泥地过渡；
- 竹子母体与竹丛；
- 灯笼、招牌、桌、长凳、酒坛；
- 柜台与床榻。

原则：先用这 20 个资产拼出一个小型“江南竹海客栈”，再扩张至桥、水岸、后厨、市场和院落。

## 4. 每个资产的生产协议

每个资产进入 `production` 前应具备：

- 唯一 `asset_id`；
- 时代与地域标签；
- 尺寸范围（米）；
- 使用场景与镜头等级；
- 材质 ID 列表；
- 可变参数；
- 是否需要 LOD / collision / sockets；
- 湿润、磨损、青苔等天气响应；
- 一张或多张验证渲染；
- QA 状态。

推荐未来把以上字段逐步加入 `asset_db/assets.json`，而不是散落在聊天记录。

## 5. 参数化母体优先级

### Door System
宽、高、单/双扇、板式、铁件、开合、破损、湿度、告示/布帘接口。

### Window System
尺寸、格栅密度、开合、破损、纸面状态、雨痕。

### Roof System
长度、坡度、瓦密度、檐口、屋脊、破瓦比例、滴水区。

### Bamboo System
高度、直径、节距、弯曲、叶量、年龄、湿度、群落密度。

### Bridge System
长度、宽度、桥面、栏杆、支撑、磨损和潮湿程度。

### Hanging System
灯笼、酒旗、门帘、绳索的挂点、长度、风向和布料响应。

## 6. GitHub / Blender 循环

当前推荐迭代环：

1. 修改脚本 / manifest / 贴图；
2. push 到 `ai/**` 分支；
3. `Blender CI` 自动执行：
   - `tools/validate_repo.py`；
   - Blender 4.5.14 LTS headless 打开 `Jiangnan.blend`；
   - `tools/ci_validate.py` 验证场景、驱动、天气、贴图和法线；
   - `tools/render_preview.py` 用 Eevee 出低成本三分之四雨景；
4. 下载 Actions artifact 检查预览；
5. 根据结果继续改；
6. 质量稳定后再运行 `Remote Render Preview` 的 Cycles 高质量版本；
7. 通过后合并到 `main`。

这样正式 Cycles 渲染不再承担“发现语法错误/驱动错误”的成本。

## 7. QA 四层

### Repository QA
文件、JSON、命名和 Python 语法。由 `validate_repo.py` 负责。

### Scene QA
场景唯一性、对象基线、相机/灯光、天气互斥、运动、驱动有效性、packed texture、代表性法线。由 `ci_validate.py` 负责。

### Visual QA
从远程预览 artifact 检查构图、材质、尺度、重复感、风向和色彩克制。目前需要视觉审查，后续可加入自动截图评分。

### Production QA
当资产进入 UE5 时再检查 LOD、collision、UV、纹理预算、Nanite 适配和性能。
